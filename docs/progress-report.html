Update - 9 Nov 2026, 2:16 AM IST: live deployment + first pushes

  • Milestone 2 DEPLOYED: live demo at https://riller.2wf0w2.workers.dev - verified end to end: rate-limit headers on every response, the login route rejects attempts past 5/minute with 429 + Retry-After, and the live chart records allowed vs rejected traffic (screenshot verified in a real browser).
  • GitHub: the repository is PRIVATE (verified: unauthenticated access returns 404) and holds both commits: c951571 (core + middleware + demo + dashboard + 14 tests) and 56560e8 (Workers deployment).
  • Runtime fix: Express's built-in JSON parsing chain (iconv-lite) cannot run on Cloudflare Workers, so the API now uses a small built-for-purpose UTF-8 JSON parser. All 14 tests still pass; behaviour unchanged.
  • Honest demo caveat: Cloudflare runs several copies of the worker (isolates), each with its own memory, so the chart shows one copy's view and very fast floods can split across copies. This is the documented in-memory limitation made visible; the planned shared store fixes it.
  • Update - 9 Nov 2026, 2:31 AM IST: shared-store milestone (M4)
  • M4 DONE (commit 0453cd6, "Add shared rate-limit store via Durable Objects and bound the public demo"): a Durable Object now holds every bucket and the stats feed, so limits hold across all copies of the worker and decisions are atomic. Verified live: 20 login attempts produced exactly 5 allowed and 15 rejected; chart totals matched curl checks exactly. Also in this push: the demo is self-defending (buttons capped at 150 in batches of 10; 10,000-bucket cap per store; 10-minute idle eviction; 1 MB body cap), the UI copy was corrected (a single request only passes while tokens remain), and a real Cloudflare constraint was found and documented (per-request pipeline, because a Durable Object stub belongs to the request that created it). Tests: 20/20. The stale status rows above were corrected in place.

Update - 12 Nov 2026, ~12:20 PM IST: the four feature upgrades (M5-M7)

The four upgrades Shubhra picked on 12 Nov (options 9, 10, 14 and 15 from the upgrade menu) are built, tested and live. M5 (commit 9ca3d1e, "Add tiered API-key plans and cost-based limiting"): /api/ledger serves free (10/min) and pro (100/min) plans with per-tenant buckets and plan-aware 429s; /api/heavy spends 3 tokens per call. Live-verified: the free key exhausts at exactly 10, the pro key continues, the heavy route rejects the 4th call with a 12-second wait. M6 (commit 6ff3b05, "Add escalating penalties (jail) to the login route"): rejections double the block (30s, 60s, ... capped at 30 min), a success forgives, and jail state lives in the shared store so it holds across isolates. Live-verified: the 6th wrong login waits 30s, a different username is unaffected. M7 (commit ca07d44, "Add a live concurrency proof for the shared store"; 0fced17 wording precision): the dashboard's Concurrency proof button fires 20 parallel requests at a fresh limit-10 key - exactly 10 allowed, live-verified in a real browser (screenshot saved). The endpoint rate-limits itself to 10 runs/min per visitor. Test suite grew from 20 to 35 tests, all passing; Documentation sections 29-32 teach each upgrade end to end (mechanism, code, alternatives, failure cases, tests).
